# Vendored conformance vector

`cross-impl-derivation.golden.json` is copied verbatim from the Plexus SDK. It is
the oracle: where this Zig port disagrees with it, this port is wrong.

| | |
|---|---|
| source | `plexus-sdk-ts/src/tests/vectors/cross-impl-derivation.golden.json` |
| generator | `plexus-sdk-ts/tools/gen-derivation-vector.mjs` |
| schemaVersion | 1 |
| sha256 | `12455c0bc0cfe43ceb5601b928ea9d95effe66b45fb31c7beebea69af2c7f012` |
| vendored | 2026-08-27 |

To re-sync after the SDK regenerates it:

```bash
cp "$PLEXUS_SDK_REPO/src/tests/vectors/cross-impl-derivation.golden.json" .
shasum -a 256 cross-impl-derivation.golden.json    # update the row above
zig build test
```

Vendored rather than read from a sibling checkout so `zig build test` cannot pass
by silently failing to find the file — it is `@embedFile`'d, so a missing vector
is a compile error rather than a skipped assertion.


## `canonical-json-escaping.golden.json`

GENERATED by `gen-escaping-vector.mjs` from the SDK's own `canonicalJson`:

```bash
PLEXUS_SDK=/path/to/plexus-sdk-ts/dist/index.js node gen-escaping-vector.mjs
```

It exists because the derivation vector does not reach string escaping at all —
its certId values are hex, an email and a dotted type name. 49 escaping cases
(quote, backslash, slash, every C0 control, DEL, 2/3/4-byte UTF-8, U+2028/9,
lone surrogates) plus 5 sort cases pinning UTF-16 code-unit key order.

Regenerate it whenever the SDK's canonicalizer changes. Unlike the derivation
vector this one is ours, so it carries no upstream sha256 — the oracle is the
SDK function it was generated from.


## `rotation.golden.json`

GENERATED by `gen-rotation-vector.mjs`, which drives the SDK's **real**
`MemoryKeyStore` through a scripted sequence and records what it returned:

```bash
PLEXUS_SDK=/path/to/plexus-sdk-ts/dist/index.js node gen-rotation-vector.mjs
```

19 steps covering allocation, burning, burning an untouched context, isolation
across resource/flag/parent, a recovery restore, and a restore that must be
refused as a rewind — plus the final high-water mark and next allocation for
every context touched.

Regenerate whenever the SDK's KeyStore semantics change. A ported test re-states
what someone believed; a replayed trace states what the SDK did.


## `cert.golden.json`

GENERATED by `gen-cert-vector.mjs` from the **TypeScript fleet plane**:

```bash
PLEXUS_SDK=/path/to/plexus-sdk-ts/dist/index.js bun gen-cert-vector.mjs
```

`validFromMs` is pinned rather than taken from the clock, because it lands in
both the payload and the cell header — a vector built from `Date.now()` would be
unreproducible by construction.

Carries two certs. The first uses the default no-expiry (`UINT64_MAX`); the
second uses a real expiry, because `UINT64_MAX` is eight `0xff` bytes and reads
the same in either endianness, so a vector with only that value cannot catch a
byte-order mistake in the expiry field.

The signature is carried to be **verified**, not compared: the two planes use
different deterministic nonce schemes and produce different valid signatures.

It also carries `hardwareParityCase` — the demo fleet the C6 boards are flashed
for — so the Zig plane's agreement with the TypeScript one is a test rather than
something noticed during a hardware run.

And it carries `domainFlags`. The conformance tests mint from THAT rather than
from `domains.zig`, so regenerating the vector without regenerating the cells —
or changing a flag in one plane only — fails instead of quietly passing. The
flag lands in three places at once: folded into the BRC-42 invoice (visible in
`derivationPath`), written to cell header bytes 24-27 (where
`OP_CHECKDOMAINFLAG` reads it), and recorded per context in `functionalDomains`
when a recipe is enrolled. Both planes must agree on all three or the cell bytes
diverge.


## `recovery.golden.json`

GENERATED by `gen-recovery-vector.mjs`, which drives the SDK's **real**
`reconstituteFromRecoveryExport` over five payloads and records what the rebuilt
allocator actually handed out:

| case | why |
|---|---|
| `honest` | what an exporter should emit |
| `poisoned` | `currentIndex` below the paths beside it — must be floored |
| `omitted` | no row at all for a triple the paths prove — the same rewind |
| `burned` | `currentIndex` above the paths, as a rotation leaves it — must survive |
| `siblings-unordered` | several rows for one triple must reduce to their max |

`check-recipe-interop.mjs` is the other direction: it feeds the SDK a recipe the
Zig plane wrote and checks the burn survived. Run it with `bun run fleet:zig:interop`.

## Cross-repo convergence vectors (option D)

snapshots** of surfaces the fleet plane shares with semantos-core, recorded here
with their source + sha256 so a stale copy is visible. On a source change,
re-vendor and bump the sha256; the parity conformances (`zig build test-bridge`,
`zig build test-domain-flags`) then confirm this plane matches the new copy.
