# Vendored conformance vector

`cross-impl-derivation.golden.json` is copied verbatim from the Plexus SDK. It is
the oracle: where this Zig port disagrees with it, this port is wrong.

| | |
|---|---|
| source | `plexus-sdk-ts/src/tests/vectors/cross-impl-derivation.golden.json` |
| generator | `plexus-sdk-ts/tools/gen-derivation-vector.mjs` |
| schemaVersion | 1 |
| sha256 | `12455c0bc0cfe43ceb5601b928ea9d95effe66b45fb31c7beebea69af2c7f012` |
| vendored | 2026-08-27 |

To re-sync after the SDK regenerates it:

```bash
cp "$PLEXUS_SDK_REPO/src/tests/vectors/cross-impl-derivation.golden.json" .
shasum -a 256 cross-impl-derivation.golden.json    # update the row above
zig build test
```

Vendored rather than read from a sibling checkout so `zig build test` cannot pass
by silently failing to find the file — it is `@embedFile`'d, so a missing vector
is a compile error rather than a skipped assertion.


## `canonical-json-escaping.golden.json`

GENERATED by `gen-escaping-vector.mjs` from the SDK's own `canonicalJson`:

```bash
PLEXUS_SDK=/path/to/plexus-sdk-ts/dist/index.js node gen-escaping-vector.mjs
```

It exists because the derivation vector does not reach string escaping at all —
its certId values are hex, an email and a dotted type name. 49 escaping cases
(quote, backslash, slash, every C0 control, DEL, 2/3/4-byte UTF-8, U+2028/9,
lone surrogates) plus 5 sort cases pinning UTF-16 code-unit key order.

Regenerate it whenever the SDK's canonicalizer changes. Unlike the derivation
vector this one is ours, so it carries no upstream sha256 — the oracle is the
SDK function it was generated from.


## `rotation.golden.json`

GENERATED by `gen-rotation-vector.mjs`, which drives the SDK's **real**
`MemoryKeyStore` through a scripted sequence and records what it returned:

```bash
PLEXUS_SDK=/path/to/plexus-sdk-ts/dist/index.js node gen-rotation-vector.mjs
```

19 steps covering allocation, burning, burning an untouched context, isolation
across resource/flag/parent, a recovery restore, and a restore that must be
refused as a rewind — plus the final high-water mark and next allocation for
every context touched.

Regenerate whenever the SDK's KeyStore semantics change. A ported test re-states
what someone believed; a replayed trace states what the SDK did.
