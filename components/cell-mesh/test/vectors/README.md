# `domainflag_vectors.h`

The OP_CHECKDOMAINFLAG truth table, generated by running the opcode.

```bash
node gen-domainflag-vectors.mjs
```

## Why this exists

The forward hot path gates on `cm_domain_flag_matches`, a `u32 ==`. Running the
cell engine per cell is not affordable next to a ~270 ms signature verify, so
the fast path is native code. That is only legitimate if the native compare *is*
the opcode — and "is" needs to be a test, not a comment.

So the oracle is not `plexus.zig`, and not anyone's reading of it. It is
`components/semantos/wasm/cell-engine-embedded.wasm` — the exact blob this
firmware embeds and flashes. The generator instantiates it, executes

```
<1024-byte cell> <expected_flag> OP_CHECKDOMAINFLAG
```

for every ordered pair of eight flags, and records accept (rc 0) or reject
(rc 28, `domain_flag_mismatch`). `test_cell_capability.c` T11 then drives
`cm_domain_flag_matches` from that table. If the two ever disagree, the C is
the side that is wrong.

The device checks it again at boot: `domain_flag_selftest()` in
`examples/mesh_demo/main/main.c` runs the real opcode through the loaded engine
for one matching and one mismatching pair, and logs `OP_CHECKDOMAINFLAG
selftest OK` — or a loud `ESP_LOGE` if the fast path has drifted.

## ⚠ The encoding trap

The opcode reads the expected flag off the stack as a **BSV script number**:
sign-magnitude, little-endian, **bit 7 of the top byte is the sign**.

A four-byte LE push of `0x80000000` is the bytes `00 00 00 80`, which is
script-number *negative zero*. The engine compares it as `0` — so a cell
declaring domain 0 **accepts** against an expected flag of `0x80000000`.
Measured, for `0x80000000`, `0xffffffff` and `0xfffffffe`: in every case the
zero cell was accepted and the matching cell was rejected.

That is a silent authorisation bypass for any flag with bit 31 set. Two guards:

- `tools/fleet-zig/src/domains.zig` has `script_safe_max = 0x7fffffff` and a
  `comptime` block that refuses to compile if a flag this layer allocates
  crosses it.
- The generator reproduces the hazard on every run and throws if the engine
  ever stops behaving this way, so the claim above cannot go stale silently.

Minimal encoding also means `0x00f10001` is **four** bytes (`01 00 f1 00` — the
pad byte is required) while `0x0e` is **one**.

## Regenerating

Rerun the generator whenever `cell-engine-embedded.wasm` changes. It is
deterministic: same blob, byte-identical header. The C test asserts the table
has both accepts and (more) rejects, so a generator that silently emitted a
degenerate all-accept matrix fails rather than passing vacuously.
